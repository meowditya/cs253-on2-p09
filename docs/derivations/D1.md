# D1 — The lazy heap stays within 2× its live size, and its operations are O(log n) amortised

**Author:** Gulam Abbas (Structure A owner) · **Roll no.** 250041016 · *draft prepared with Claude, declared in TOOLS.md*

**Statement** (project document, Project 9, D1): *With purging whenever cancelled entries exceed live ones, heap size stays within a constant factor of the live count, and each operation costs O(log n) amortised. Prove it.*

**Setting.** L = live (pending) entries, C = cancelled entries still in the array, m = L + C. After
every successful `cancel` and after every `pop_min`, the heap purges if C > L. A purge rebuilds the
array from the live entries only (C becomes 0).

## Claim 1 — m ≤ 2L after every public operation

Induction over operations; invariant: C ≤ L. Initially L = C = 0.
- `insert`: L + 1, C unchanged — still C ≤ L.
- unsuccessful `cancel`: nothing changes.
- successful `cancel`: L − 1, C + 1; if now C > L, the purge sets C = 0.
- `pop_min`: discarding cancelled roots only lowers C; removing the live minimum lowers L by 1; then the
  same purge check runs.
- `peek_min`: only lowers C. `successor`, `size`: change nothing.
So C ≤ L after every operation and m = L + C ≤ 2L (m = 0 when L = 0).

**Why the check after pop is necessary.** Insert 1000 events, cancel the 499 latest (C = 499 ≤ L = 501,
no purge), pop the 500 earliest. Without the post-pop check L = 1, C = 499, m = 500 = 500·L, and the
ratio grows without bound with the initial size. (`tests/test_structA.cpp`, `gen drain`.)

## Claim 2 — amortised cost

Assume O(1) expected cost per hash-table operation, and amortise vector growth and table rebuilds
separately (standard doubling arguments). Potential

  Φ = a · C · log₂(m + 1),  a constant to be chosen.  Φ ≥ 0 and Φ = 0 initially.

- **cancel** (C+1, m unchanged): ΔΦ = a·log₂(m+1). Actual cost O(1). Amortised O(log m).
- **stale-root removal** (C−1, m−1): Φ falls by a·C·log₂(m+1) − a·(C−1)·log₂ m
  = a·log₂(m+1) + a·(C−1)·(log₂(m+1) − log₂ m) ≥ a·log₂(m+1). That pays its sift-down (O(log m)) and
  table erase for a large enough a. Each stale entry is removed at most once.
- **purge** (C > L, so m < 2C): costs at most b·m. Φ drops from a·C·log₂(m+1) ≥ a·C ≥ a·m/2 to 0. With
  a ≥ 2b the purge is free in amortised terms.
- **insert** (m+1, C unchanged): ΔΦ = a·C·log₂((m+2)/(m+1)) ≤ a·C/((m+1)·ln 2) ≤ a/ln 2, because C ≤ m
  and log(1+x) ≤ x. Actual sift-up O(log m). Amortised O(log m).
- **live removal** (m−1, C unchanged): ΔΦ ≤ 0; its own sift-down is O(log m).

Since m ≤ 2L + 1 at every boundary, log m ≤ log(L + 2) + 1. Hence insert, cancel, pop_min and peek_min
cost expected amortised O(log(L + 2)). (Purging alone could be paid by Φ' = 2b·C, giving O(1) amortised
purge cost per cancel.) `successor` is excluded: the heap answers it by a pruned search that can visit
all m entries. ∎
