# D5 — At most one rebalance per AVL insertion; ascending order forces one on almost every insertion

**Author:** Sanchit Goyal (Adversary) · **Roll no.** 250041035 · *draft prepared with Claude, declared in TOOLS.md*

**Statement** (project document, Project 9, D5): *Each AVL insertion performs at most one single or one double rotation. Prove it, and construct an insertion order that forces a rotation on a constant fraction of insertions.*

A *rebalance* is one single rotation or one double rotation (= two primitive rotations).

## Claim 1 — each insertion performs at most one rebalance

Insertion adds a leaf; only the leaf's ancestors can change height or balance. Walk up. If no ancestor
becomes unbalanced, nothing happens. Otherwise let x be the **lowest** unbalanced ancestor. Before the
insertion x had height h + 1, its taller side now has height h + 1 and the other side h − 1.
- LL/RR case: one rotation at x makes the taller child the subtree root, with two children of height h:
  the subtree height is h + 1.
- LR/RL case: a double rotation makes the inner grandchild the root, again with two children of height
  h: height h + 1.
Either way the subtree at x is back to its pre-insertion height h + 1, so every ancestor above x sees no
change and needs no repair. ∎ (Deletion has no such height-restoring property and can cascade: one
delete-min on a height-27 Fibonacci tree performs 13 rotations — `gen fib-delete 27 1`.)

## Claim 2 — ascending insertion rotates on all but O(log n) insertions

Insert 1, 2, …, n. Each new key is the largest, so it becomes the right child of the current maximum,
and its only ancestors are the nodes of the **right spine** (root, root.right, …).

**Lemma.** After inserting 1..k: (a) the maximum is a leaf, and (b) every right-spine node has balance
0 or −1 (never left-heavy).
*Proof by induction.* True for k ≤ 1. Assume it before inserting k + 1. The new leaf hangs under the
old maximum (a leaf by (a)), so it is the new maximum and a leaf — (a) holds.
- If every old spine node had balance 0, each becomes −1 and grows by one level; no rotation; (b) holds.
- Otherwise let x be the lowest old spine node with balance −1; every spine node below x was balanced,
  so the growth reaches x. Let y = x.right, h(x.left) = a, h(y) = a + 1; y was balanced, so both its
  children had height a. After the insertion y.right has height a + 1: y is −1 and x is −2, and a single
  left rotation at x fixes it. Now old x has two children of height a (height a + 1, balanced), and y has
  two children of height a + 1 (height a + 2 = x's old height, balanced). Nodes above keep their height
  and balance. The new spine runs through y (balance 0) and then the old spine below y, whose nodes went
  from 0 to −1. So (b) holds. ∎

**Consequence.** A rotation-free insertion raises the tree's height by exactly 1; an insertion with a
rotation keeps it. The height starts at −1 and ends at h < 1.44042…·log₂(n+2) − 1.32772… (D2, exact
constants 1/log₂φ and log_φ√5 − 3), so the number of rotation-free insertions, h + 1, is less than
1.44042…·log₂(n+2) − 0.32772… < 1.45·log₂(n+2), and **at least n − 1.45·log₂(n+2) insertions rotate** — a
fraction tending to 1. ∎ (Rounding the constants must not tighten the bound: round the slope UP and the
constant term UP, e.g. 1.4405 and −1.3277, or use the simpler 1.45·log₂(n+2).)

**Measured** (`gen ascending N` + `replay --stats`): N = 1000 → 990 rebalances; N = 10⁶ → 999 980, all
single, rotation-free exactly at k = 1, 2, 4, …, 2¹⁹. The "exactly at powers of two" pattern is an
observation; the proof above shows only the n − O(log n) bound, which is what the handout asks for.
`gen zigzag` (1, N, 2, N−1, …) instead mixes in many double rotations (617 of 988 for N = 1000).
