# D4 — The AVL checker accepts exactly the valid AVL trees

**Author:** Hiransh Anand (Oracle owner) · **Roll no.** 250041018 · *draft prepared with Claude, declared in TOOLS.md*

**Two predicates.**
1. *AVL tree validity:* a finite rooted binary tree with strict BST order on keys, every stored height
   equal to the true height, and every node's subtree heights differing by at most 1.
2. *Queue representation validity:* (1) plus: every index in range, NIL untouched, no node reached
   twice, every reachable seq unique and issued, reachable count = size(), and every non-NIL pool slot
   either reachable or on the free list (not both, no duplicates).

Stored heights belong in (1) because insertion and deletion read them to decide rotations: a tree that
is balanced but stores a wrong height will be mis-rebalanced later.

**The checker** (`oracle/checkers.cpp`, `check_avl_view`).
- *Structural pre-pass:* an iterative walk from the root that rejects an out-of-range child index and
  any node reached twice (a cycle or a shared child). So the rest runs on a finite proper tree and
  cannot loop or overflow the stack.
- *Post-order pass* (reverse preorder, so children come before parents): for each node compute
  th = 1 + max(th(left), th(right)) with th(NIL) = −1, and the subtree's minimum and maximum keys, from
  the children's computed values — never from stored fields. Test max(left) < key < min(right),
  stored height = th, and |th(left) − th(right)| ≤ 1.
- *Representation checks* as in (2).

**Correctness.** By induction on subtree size, if no test failed below a node, the computed (th, min,
max) are the true values for its subtree (base: NIL; step: the definitions).
- *Sufficient:* if every test passes, then at every node max(left) < key < min(right), which (with true
  extremes) is exactly the BST property for distinct keys; stored heights equal true heights; and true
  balance factors are in {−1, 0, 1}. So the tree is a valid AVL tree; the representation tests then give
  (2).
- *Necessary:* in a valid AVL tree none of the three node tests can fail, and in a valid representation
  none of the structural or representation tests can fail.
- The node tests check exactly the three conditions of (1) — nothing stronger (no "complete tree"
  requirement), nothing weaker. The wrapper adds exactly the conditions of (2). ∎

**Evidence that it bites** (`tests/test_checkers_mutations.cpp`): stale height, child out of range,
cycle, shared child and leaked pool slot are each rejected; the correct tree is accepted.
